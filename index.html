sesync v0.1.0 · MIT · Linux and Windows builds

One conversation, every harness.

Start a conversation in omp, continue it in Pi, pick it up in OpenCode, resume it in Claude Code or Antigravity. sesync converts each copy, keeps them in step, and locks the conversation while a turn is running.

A TUI on the machine, a popup inside herdr, a bridge for the phone, and prompts that travel from one machine to another.

Download v0.1.0 Source on GitHub See the herdr popup

What it is

A conversation has one source: the harness where it is live. Every other harness you chose gets a converted mirror. Answering inside a mirror moves the source there. The other mirrors then follow.

→
Mirror: Pi
Mirror: OpenCode
Mirror: Claude Code
  • Turn-taking. A reply typed into a mirror makes that harness the source.
  • The lock. A conversation is locked while a harness takes a turn. The lock is claimed at turn start and released at turn end. An idle conversation holds nothing. A refused claim blocks the prompt and names the holder.
  • Mirrors are derived. A mirror is rebuilt from its source. The daemon skips any conversation that is locked.
  • Archive before replace. Bytes that sesync did not write are archived before anything replaces them.

The format converter is sesync-conv. The omp/Pi journal is the interchange format. Reasoning content is kept for omp, Pi, OpenCode and Antigravity, and dropped for Claude Code, which signs its own reasoning blocks.

The TUI

Run sesync --tui. The tabs are Sessions, Team and Machines. The command palette is ctrl+p. The divergence dialog opens when two copies of a conversation have moved on separately. Open in herdr (o) opens the selected session in herdr.

Divergence dialog

When two copies of a conversation each have new turns after their common history, the dialog shows both sides. It offers five choices and "decide later". Every choice except "decide later" keeps both histories.

Full details: docs/ARCHITECTURE.md.

The herdr popup

herdr is a terminal multiplexer for coding agents. Add this to ~/.config/herdr/config.toml, with sesync on herdr's PATH:

[[keys.command]]
key = "ctrl+alt+s"
type = "popup"
command = "sesync --tui"
description = "sesync: open a session"
width = "90%"
height = "85%"

Press ctrl+alt+s in herdr to open the TUI as a popup. Pick a session and choose Open in herdr. If a herdr pane already runs that session, its tab is focused. Otherwise a new tab opens in the session's directory and types the harness's resume command.

Phone app control

The Agent Hub app for Android runs the bridge's protocol. It is built on Orca's mobile protocol. The bridge is sesync bridge serve. It listens on 0.0.0.0:6768 by default.

Pairing

sesync bridge pair --endpoint ws://HOST:6768 --label phone

This prints a pairing offer, an agenthub://pair?code= URL and a terminal QR code. The device token appears only in that output. --endpoint is the address the phone dials. If you omit it, the endpoint value from the settings file is used. If neither is set, pairing stops and asks for one. Nothing here opens a firewall port.

Show the QR code only to the phone being paired. Whoever can read the offer can pair. Remove a device with sesync bridge revoke <device-id>. Its token is refused on the next frame.

What the phone can do

  • List conversations, with their project and herdr status.
  • Read each transcript, and open its herdr pane live.
  • Send prompts and answer approvals.
  • Send images, and send or receive files.
  • Dictate prompts (needs a Whisper-compatible server).
  • Start new sessions.
  • Receive push notifications through ntfy, when ntfy is configured.
  • Show plan usage, read from omp usage --json.
  • Set the "can see" switch. It links one paired machine to another, so each machine can reach the other.

Encryption

  • Machine links (sesync machine) use a hybrid handshake: X25519 + ML-KEM-768, with AES-256-GCM frames. A bridge that answers only with the legacy channel is refused.
  • Phone link uses Orca's legacy channel: X25519 + XSalsa20-Poly1305. This is classical, not hybrid. The bridge's docs say it is acceptable only because it runs inside WireGuard, which is also classical, until the app speaks the hybrid hello.
  • The bridge is authenticated by its pinned X25519 key. Tokens are 256 random bits, and only their SHA-256 is stored.

Settings file

~/.config/sesync/bridge/settings.json holds this machine's values. All keys are optional. A flag wins over the file. An unknown field or invalid JSON stops the bridge and names the file.

{ "endpoint": "ws://HOST:6768",
  "allow": "127.0.0.0/8,10.0.0.0/8",
  "ntfyUrl": "https://NTFY_HOST", "ntfyTopic": "agents", "ntfyTokenCommand": "cat ~/.config/ntfy-token",
  "whisperUrl": "http://WHISPER_HOST:8080/v1/audio/transcriptions",
  "whisperModel": "MODEL", "whisperLanguage": "en" }

The default allowlist is loopback, the private ranges and the shared VPN range (100.64.0.0/10). Without ntfy settings, push is off.

Full details: docs/BRIDGE.md.

Machines

One sesync machine can drive another's conversations. Pair them with sesync bridge pair --label <this machine> on the other machine, then add it here.

sesync machine add <name> <pairing link>
sesync machine list [<name>]
sesync machine attach <name> <conversation title or id> [--open]
sesync machine prompt <name> <conversation> <text | -> [--open] [--wait[=<seconds>]]
sesync machine read <name> <conversation> [<count>]
sesync machine send <name> <file or folder>
sesync machine get <name> <path on that machine> [<folder here>]
sesync machine endpoint <name> <ws://address> | --clear
sesync machine remove <name>

Agents prompting agents

An agent can use the prompt-agent-over-bridge skill from skills/ to ask an agent on another machine. prompt claims the conversation's lock for the turn. It refuses a pane that is waiting on a question, and a closed conversation unless --open is given.

A paired phone can type into your agents. Treat each paired machine the same way.

Install

From a release

Download an archive from GitHub Releases. Each release ships three binaries (sesync-lock, sesync-conv, sesync), the hook files and a SHA256SUMS file. The archives are tar.gz for Linux and macOS and zip for Windows. The binaries are not signed.

From source

You need Rust (stable). Build the three binaries, then copy them onto your PATH:

cargo build --release --manifest-path sesync-lock/Cargo.toml
cargo build --release --manifest-path sesync-conv/Cargo.toml
cargo build --release --manifest-path sesync/Cargo.toml

install.sh (Linux and macOS)

Run sh install.sh. It builds the three binaries with cargo build --release, then installs them into ~/.local/bin. The hook files go into ~/.local/share/sesync/hooks. A MANIFEST lists every file it wrote. On Linux with systemd it writes ~/.config/systemd/user/sesync.service and enables it, so the daemon starts at login. The other options:

  • --prefix DIR: install under DIR.
  • --no-service: do not register the login service.
  • --no-build: use already-built release binaries.
  • --uninstall: stop the service and remove exactly the files in the manifest.

install.ps1 (Windows)

Run powershell -ExecutionPolicy Bypass -File install.ps1. It needs no administrator rights. It writes only under %LOCALAPPDATA%\Programs\sesync, plus two per-user settings. It adds the bin folder to the user PATH (in HKCU\Environment), and adds a login start entry under HKCU\...\Run. The options are -NoService (skip the login entry) and -Uninstall.

Hooks per harness

HarnessHook
omp and Pihooks/omp-lock-shim.ts, an omp extension. Claims on turn_start, releases on turn_end and session lifecycle events.
Claude Codehooks/claude-hook.sh, wired to UserPromptSubmit (claim, block on refusal) and Stop / SessionEnd (release).
OpenCodeA plugin that claims on chat.message and releases on session.idle and session.deleted.
Antigravity CLI (agy)No hook yet. The daemon still claims the lock for every write, refuses to refresh a copy that agy holds open, and archives any agy turn it would replace.
